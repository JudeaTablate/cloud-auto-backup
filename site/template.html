cloud-auto-backup · v$version

My repo, up in the clouds, every Sunday at 00:00 UTC.

A small Python tool I wrote so my code always has a copy somewhere that isn't GitHub. It zips the tree, writes a SHA-256, ships both through rclone, and throws away the old ones.

FL350FL240FL120FL050GND

GND Before takeoff

You need Python 3.11+ and rclone with a remote already configured. The package itself uses only the standard library.

~ pip install git+$repo
~ rclone config            # make a remote called "gdrive"
~ cab run --dry-run         # see what would go up

FL050 What one run looks like

00:00:04  packed   repo_backup_2026-11-29_00-00.zip  (37 files, 48.2 KB)
00:00:04  sha256   9f2c…e41a
00:00:07  uploaded -> gdrive:Backups
00:00:08  pruned   repo_backup_2026-10-04_00-00.zip
00:00:08  pruned   repo_backup_2026-10-04_00-00.zip.sha256

The zip is built in a temp directory, never inside the folder it's archiving, so it can't swallow itself. .git, caches and old zips are skipped.

FL120 How it flies

  1. configdefaults ← [tool.cab] in pyproject ← CAB_* env ← flags
  2. archivewalk the tree, apply excludes, deflate, hash
  3. remoterclone copyto for the zip and its .sha256
  4. retentionkeep the newest N, delete the rest (sidecars too)

Every rclone call goes through one function, so the tests run against a fake remote and never touch a real drive.
